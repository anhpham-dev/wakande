A LANGUAGE IN THE MAKING

Meet Wakande.

A small programming language, built from scratch in Python. Follow an expression from its first character to its final value.

This documentation website was AI-generated. The Wakande programming language and its interpreter were written by hand by anhpham-dev.

02 / FIRST STEPS

Getting started

You need Python 3.10 or newer and Git to clone the repository. The interpreter uses the Python standard library, so there are no packages to install.

Run the built-in demo

Terminal
git clone https://github.com/anhpham-dev/wakande.git
cd wakande
python3 wakande.py

On systems where Python is invoked as python, use that command instead. The demo evaluates let x = --5, let y = 10, and x + y.

Output
Result: 15
Variables: {'x': 5, 'y': 10}

Run your own source

Create run_example.py in the repository root and use the three interpreter stages directly:

run_example.py · Python
from lexer import Lexer
from parser import Parser
from interpreter import evaluate

source = """let price = 12
let quantity = 3
price * quantity
"""

tokens = Lexer(source).tokenize()
program = Parser(tokens).parse()
environment = {}
result = evaluate(program, environment)

print("Result:", result)
print("Variables:", environment)

Run python3 run_example.py. The result is 36, and the environment contains price and quantity.

Read a .wak file

Save supported Wakande syntax in a file such as wak_code/calculation.wak. In your Python runner, replace the source assignment with:

Python
from pathlib import Path

source = Path("wak_code/calculation.wak").read_text(encoding="utf-8")

Run the runner from the repository root so that this relative path resolves correctly. wakande.py currently runs a fixed demo; it does not accept a filename argument or provide a REPL.

03 / THE REFERENCE

The language, today

A program is a sequence of declarations and expressions. Separate statements with a newline. Blank lines, spaces, and tabs are accepted; semicolons and comments are not supported.

Numbers

Write integers as 42 and decimals as 3.14. Negative values use the unary minus operator, as in -5. Use digits on both sides of the decimal point: 0.5 works, while .5 and 5. do not. Exponent notation such as 1e3 is not supported.

Arithmetic & precedence

Operators from highest to lowest precedence
OperatorMeaningExampleValue
(…)Group an expression(2 + 3) * 420
- (unary)Negate a value--55
*, /Multiply, divide7 / 23.5
+, -Add, subtract10 - 3 + 18

Operators at the same precedence evaluate from left to right. Multiplication and division bind more tightly than addition and subtraction, so 2 + 3 * 4 produces 14. Unary plus, powers, and modulo are not implemented.

Integers and floats can be combined: 1 + 2.5 produces 3.5. Arithmetic follows Python's numeric behavior; division returns a float and division by zero raises an error.

Variables

Declare a variable with let name = expression, then refer to it by name. Names are case-sensitive. They begin with a letter or underscore and continue with letters, digits, or underscores. The lexer uses Python's character checks, so it also accepts Unicode letters. let is the only reserved keyword.

Wakande
let total = 20
let total = total + 5
total

The final value is 25. A second let with the same name overwrites its stored value. Bare reassignment such as total = 25 is not supported. A name must already exist before you use it in an expression.

Program results & environments

The evaluator returns the value of the last statement, including a declaration's assigned value. An empty program returns Python's None. Variables live in the dictionary passed to evaluate; use a new dictionary for a fresh run, or reuse it to keep bindings across evaluations. There are no function or block scopes yet.

=
The equals sign belongs to declarations.

= sets the initial value in let x = 5. It is not a comparison operator in the current interpreter.

05 / UNDER THE HOOD

From text to a value

The interpreter has three stages. Each stage transforms the output of the one before it.

  1. 01LexerText → tokens
  2. 02ParserTokens → tree
  3. 03EvaluatorTree → value

1. Tokenize the source

lexer.py ↗ reads characters and produces Token objects with a kind, value, line, and column. Positions start at 1. Newlines become NEWLINE tokens, and every token stream ends with EOF.

Token kinds for 2 + 3 * 4
NUMBER PLUS NUMBER STAR NUMBER EOF

2. Build an abstract syntax tree

parser.py ↗ uses recursive descent. parse_factor handles numbers, variable references, parentheses, and unary minus; parse_term handles multiplication and division; parse_expression handles addition and subtraction. parse_program collects statements into a Program.

Tree shape for 2 + 3 * 4
BinaryExpression (+)
├── Number (2)
└── BinaryExpression (*)
    ├── Number (3)
    └── Number (4)

ast_nodes.py ↗ defines six dataclasses: Number, BinaryExpression, Variable, VariableDeclaration, Program, and UnaryExpression. Expression operators hold the lexer tokens used by the evaluator.

3. Evaluate the tree

interpreter.py ↗ walks the tree recursively. It evaluates operands, applies arithmetic, stores declarations in the environment, and looks up variable references. For a Program, it evaluates statements in order and returns the last value.

Inspect a run

Add these lines to your Python runner after parsing and evaluating:

Python
for token in tokens:
    print(token)

print(program)
print(environment)
06 / WHEN SOMETHING BREAKS

Errors & debugging

Lexer and parser failures generally raise ValueError. Some include a line and column. Runtime failures use Python exceptions; the demo does not catch them, so you will see a traceback.

Common errors and how to resolve them
InputWhat happenedHow to fix it
12scoreInvalid number identifierStart a name with a letter or _; separate numbers and names with an operator.
2 +Expected an expressionProvide the right operand on the same line.
(2 + 3Expected )Close the opening parenthesis.
let = 5Expected a variable namePut an identifier after let.
let x 5Expected an equal signUse let x = 5.
missing + 1Undefined variableDeclare missing before using it.
1 2Expected newline or EOFAdd an operator or put the second statement on a new line.
"hello" or 1;Invalid characterUse supported numeric syntax and newline separators.
1 / 0ZeroDivisionErrorUse a nonzero divisor.

Expressions cannot continue across newlines, even inside parentheses. If an error is unclear, inspect the token stream first, then the parsed tree. When evaluating into a reused environment, declarations completed before a runtime error remain in that dictionary.

When extending Wakande, update the lexer, AST nodes, parser, and evaluator as needed. Check both a successful example and an invalid input, then update these docs to describe the new behavior.

08 / ON THE WEB

Host on GitHub Pages

This documentation is a static site. All assets live in docs/ and use relative paths, so it works under the repository's /wakande/ URL. No build or dependency installation is required.

  1. Commit and push the docs/ folder to the branch you want to publish.
  2. In the GitHub repository, open Settings → Pages.
  3. Under Build and deployment, choose Deploy from a branch.
  4. Select your publishing branch and the /docs folder, then click Save.

With the default GitHub Pages domain, this repository's site will be at anhpham-dev.github.io/wakande/ once deployment succeeds. Check the repository's Pages settings or Actions runs for deployment status. See GitHub's publishing source guide ↗ for details.

Preview locally

From the repository root, run:

Terminal
python3 -m http.server 8000 --directory docs

Open localhost:8000. Edit docs/index.html for content, docs/assets/styles.css for appearance, and docs/assets/app.js for search, navigation, theme selection, and copy buttons.
